# MoneyHub - notes for Claude Code (read this first)

Local creator tool: generates sellable digital products (planners, trackers, journals, worksheets, cards, wall art, ebooks), listing kits, Pinterest pins, launch videos. The owner uploads manually; there is no marketplace publishing by design.

## Run it (macOS M4 / Linux)
```
bash scripts/setup.sh && source .venv/bin/activate
moneyhub doctor            # fix whatever it reports first
pytest -q                  # ~3.5 min; expect 230ish passed, 1 skipped
moneyhub make "nurse" weekly_planner --llm builtin   # offline smoke test
moneyhub ui
```
`claude -p` is the default LLM; `--llm builtin` forces offline. Config: `moneyhub.yaml` (provider chains per task: content, listing, research, motion).

## Layout
- `src/moneyhub/products/` generators (+ `templates/*.j2`), `listing/` kit + marketplace guides, `render/` (WeasyPrint/Playwright PDF, Pillow graphics, motion engines), `brag/` launch videos, `qa.py`, `risk.py`, `growth.py`, `cli.py`, `web/`.
- `engines/` optional Remotion/Manim, `editor/penpot/`, `docs/` (research, licenses, brag.md, editing.md).

## Conventions
- Python 3.11+, Typer CLI, Pydantic models, pytest in `tests/`. Match surrounding style; keep comments sparse.
- New product type: subclass in `products/`, register in `registry`, add `_TYPE_WORDS` entry in `listing/kit.py` (a test enforces it), add tests.
- Generated output goes to `out/` (not committed). Never commit API keys.
- Marketplace rules matter: Etsy AI disclosure line in descriptions, no trademarked/brand terms (see `risk.py`), Pinterest text outside the bottom 20% safe zone, QA must pass before a product is "ready".
- No PRs or pushes unless the owner asks.

## More things to know
- **WeasyPrint + CSS grid**: a `display:grid` page containing nested flex tables can intermittently take ~15 minutes to lay out (same input, random run). The budget pages use flex rows for that reason; prefer flex for anything that holds `.tbl` tables. After code changes, restart `moneyhub ui` (a running UI keeps old Python but reads new templates, which gives 500 errors).
- **Guided UI**: `/` landing, `/make` 3-step wizard (`web/templates/start.html`, `web/static/start.js`), `/docs` user guide, `/settings` keys. Everything in the UI is also a CLI flag; keep them in step (`moneyhub styles` lists the options).
- **Page layouts**: `layouts.py` holds layout specs (weekly, daily). Presets + `auto:N` generated + AI "described" layouts. To give another product type layouts: add a spec model/presets/random generator there, read `spec` in its template, set `layouts`, `auto_layout`, `layout_marker` on the class, and add a fit check like `weekly_planner.py`.
- **Keys**: `keystore.py` writes a git-ignored `.env` (0600); never put keys in yaml or code. Settings endpoints are local-only (Host/Origin checked).
- **Exports**: `exports/` has kdp, notion, canva (`moneyhub export ...`). KDP numbers (gutter, paper thickness, bleed) come from KDP's help pages; confirm them before relying on them.
- **Video engines** (`render/motion.py`): pillow (default), remotion, manim, hyperframes. HyperFrames telemetry is switched off in code.
- **Recording the tour**: `python scripts/record_tour.py` re-makes `web/static/media/*.mp4` from the real UI (offline, temp data, natural voice if installed). Re-run it when the wizard changes.
- Tests: ~290, about 4 minutes (`pytest -q`). CI is `.github/workflows/ci.yml` (not yet run on GitHub).

## Newer products and tooling (24 product types)
- Added since the first list: `activity_book` (`activities.py`: mazes with answers, dot-to-dot, tracing, odd-one-out), `learning_workbook` (`learning.py`: 10 worksheet types, 6 focuses, bilingual), `character_clipart`, `icon_pack`, `montessori_cards` (three-part cards), `classroom_pack` (name tags, desk plates, charts, calendar; `--names`), `visual_schedule` (`schedules.py` pictograms + feelings faces; boards and cards with hook-and-loop dot guides; never write the trademark "Velcro" in listing text). Kids art lives in `kidsart.py` + `kidsart_extra.py` (80 figures, 26 themes).
- **Translations** (`translations.py`): es/fr/de word lists are guarded. QA fails until `moneyhub translations check` (AI proofread) and a human `moneyhub translations approve`. New translated words go in `translations.py` only.
- **SVG assets** (`svgassets.py`, `moneyhub assets ...`): licence-checked Tabler/Lucide fetcher plus your own folder. Accepts MIT/ISC/Apache/CC0/PD/CC-BY 4.0; refuses CC-BY-SA, NC, GPL. Wall art can use `icon:<set>` motifs; `docs/licenses.md` has the detail.
- **Mockups** (`render/mockups.py`): in-use scenes for every family (`FAMILIES`); products put single designs in `meta["mockup_tiles"]` via `mockups.save_tiles`.
- **Platform packs** (`listing/platforms.py`): Etsy/Gumroad/Payhip/Ko-fi zips via `moneyhub export pack <id> <platform>`.
- **Craft outputs** (`craftbuild.py`): optional extra deliverables built with the tools, off by default (`craft.outputs.*`): `vectors` (AI/EPS/PDF/layered PSD of poster designs), `sheets` (CSV/HTML of every xlsx sheet), `pdfs` (title/author), `docx` (wordcraft: editable .docx of guide/worksheet/checklist/journal text from spec content; verified with the real wordcraft on a guide). Written to `product/Editable-files/`, each re-opened and checked (PSD needs >=2 layers; a flat PSD is deleted), failures listed in `craft-build.json`, one warn-only QA line. `moneyhub export craft <id>`, `moneyhub tools --outputs ...`, Settings panel. Editable SVGs (`editable.py`) wrap every object in `<g id="Title-Cased-Name">` (e.g. Background, Motif-3, Quote; the object keeps its own lower-case id) and split poster motifs per piece so PSD export has layers. PSD text is live text when photocraft is switched on (`craftbuild.live_text`: deletes the picture text layers and `type.create`s real ones from `posters/design-NN.text.json`; kept only if layer count, Type layers and TySh blocks check out), otherwise pictures. `sheets`, `pdfs` and `docx` were run for real on scratch products (all ok); opening the results in Excel/Word/Numbers is still the owner's.
- **Craft tools guide**: `docs/craft-tools.md` is the full user guide (install, switches, commands, per-tool checks, troubleshooting). The tour has a `tools` segment (`record_tour.py` -> `tools.mp4`, shown in `/docs`).
- **Craft tool switches**: `craft:` in `moneyhub.yaml` (master `enabled`, `verify_after_make`, per-tool `tools:`; ALL off by default). Change them in Settings (`/settings`), with `moneyhub tools --master --enable pdfcraft,gridcraft --verify-after-make`, or in `moneyhub.local.yaml`. When off, no tool is ever started and generation is unchanged; when on, `crafttools.second_opinion` adds one warn-only QA line and swallows every error. A tool that is switched off is never executed.
- **filmcraft video engine** (`render/motion.py` `FilmCraftEngine`, switch `craft.tools.filmcraft`, in `CHECKERS` so Settings/CLI list it): scene stills + `timeline.place` + cross-dissolves, exported h264; checks the video length and returns None on any failure so the chain continues. Run for real (11.21 s vs 11.2 s). Slideshow only; effectcraft not built (needs a design decision). Settings page gained one checkbox, so tutorials/tour are stale until re-recorded.
- **Brag voice-over polish**: `brag/pipeline.py` calls `crafttools.polish_wav` on every `vo-NN.wav` right after synthesis (same switches; no change when off). Run for real on a stereo 44.1 kHz WAV (peak 0.12 -> 0.90, length and rate kept); not yet listened to on a real launch video.
- **Tour narration polish**: `scripts/record_tour.py` levels its narration mix with `crafttools.polish_wav` (soundcraft `convert --normalize`, scaled back to 0.9 peak) when the master switch and the soundcraft switch are on; otherwise or on any failure the original mix is used unchanged.
- **Craft tools** (`crafttools.py`, `scripts/install_craft_tools.sh`, installed into git-ignored `tools/craft/`): third-party storytold CLIs (vectorcraft, pdfcraft, gridcraft, photocraft, wordcraft, deckcraft, soundcraft, cadcraft, plus lightcraft/designcraft/effectcraft/filmcraft). `moneyhub tools` lists them, `moneyhub verify <id>` opens a product's PDFs, xlsx, editable SVGs, listing images and DXFs with the matching tool and writes `craft-verify.json` (advisory, never part of the QA gate), `moneyhub craft <tool> ...` runs any of them. Verified on real products: pdfcraft, gridcraft, photocraft, cadcraft and vectorcraft open our files. For cut files cadcraft also checks DXF size and units (`crafttools.dxf_size_check`: inches declared, inside the mat, same width/height as the SVG; warn-only inside the second-opinion line; run for real on a scratch product, 3 of 3 matched). gridcraft opening an xlsx is not proof that Excel or Numbers recalculate it, and these are unaudited programs: Claude Code's permission check blocks running them, so the owner runs them with `!`.
- **PDFium is not thread-safe**: `render/pdfium_safe.py` (installed from `moneyhub/__init__.py`) puts one lock around every pypdfium2 call. Without it the UI crashed (trace trap / bus error) when a product page loaded many previews at once. Keep PDF rendering going through pypdfium2 so the lock applies. The lock also covers pypdfium2's garbage-collection finalizer (`bases._close_template`), and `moneyhub ui` sets `MONEYHUB_ISOLATE_PDFIUM=1` so `raster.render_pages` draws previews in a child process (`render/pdfium_worker.py`): a pdfium segfault (seen once, in `FPDF_LoadPage` on a worker thread, 2026-10-13) then fails one preview instead of killing the UI. Generation from the CLI stays in process.
- A failed generation now removes its folder (`pipeline.generate`), so no empty folders appear in `out/products`.
- Tests: ~565, about 8 minutes. Use `pytest -q --basetemp=<scratch dir>` and delete it afterwards; the data volume runs near full. The HyperFrames render test skips below 1 GB free disk.

- **`presentation_template`** (`products/presentation_template.py`, `presentations.py`): 12-slide editable `.pptx` built with the deckcraft tool (needs it installed; the craft switches do not matter), PDF preview, one editing-guide PDF (the generic Start-Here is skipped for this type). Niche-free ("<Palette> Clean ... Presentation Template"), pseudo size `deck`. Listing photos come from portrait overview sheets (`art_previews`). New hooks: `ProductType.use_faq`, `ProductType.extra_tags`, `meta["etsy_category"]`, QA `_pptx_checks`. Real font family names go through `presentations.family`. `docs/what-to-upload.md` lists what to upload on each platform. Not checked in real PowerPoint/Keynote/Google Slides.

- **Audience fit** (`web/guide.py` `FIT`, `default_fits`): the wizard shows only the products that suit the chosen audience (rest behind "Show all"); a typed audience gets the 10 audience-specific types first. The offline Ideas brainstorm (`ideas.py`) pairs audiences only with `FIT` products. Add a new product type to the `FIT` lists of the audiences it suits (a test checks every card's suggested product is in its list). Product options (theme, names, deck...) live in `#product-opts` on step 2, outside the "I'll pick" block, so they show in "Choose for me" mode too.
- **Video tutorials**: `scripts/record_tutorials.py` records 17 narrated tutorials (13 in the app, 4 in a terminal window replaying real command output) to `web/static/media/tutorials/` with `index.json`; the `/tutorials` page lists the ones that exist. Re-run it (or `--only key`) after wizard, Settings or product-page changes, together with `record_tour.py`.

- **Floral and picture backgrounds** (`decor.py` `floral_art`, `PIC_PREFIX`, `background_pictures()`): `floral` = four seeded bouquets (21/32/15/24 em) in `.page::before` at z-index 2 so the white boxes do not hide them; `pic:NAME` = big thin-line picture tile (22 em) over the page; opacities `FLORAL_OPACITY`/`PIC_OPACITY` are capped so `tint()` passes the contrast test in every palette. Real planners made with both (nurse weekly #90 stethoscope, #91 floral) and viewed.
- **Numbered backgrounds** (`decor.py` `auto_recipe`, `FILLS`, `/backgrounds` gallery, wizard "Numbered design" + `#decor_bg_no`): `--decor-background auto:N` (1..1000) builds N from the 36 `patterns.KINDS` plus 6 CSS fills (solid, gradient, grid, stripes, frame, paper); laps change colours/size/angle/seed; fills are plain CSS (WeasyPrint draws gradients and borders, not box-shadows). About 868 of 1000 differ with one palette. Contrast uses `tint()` (also covers fills). Run on a real weekly and daily planner (PASS). Wizard changed: re-record the decoration tutorial and the tour.
- **Page decoration** (`decor.py`, off by default): three layers (corner art `.page::after`, title-bar pictures `.hdr-art` span from the `header` macro, pale background `.page::before`), strengths light/medium/bold, themed picture sets per audience (`THEMES`, `NICHE_THEME`, `theme_for`). Stored in `style.extra["decor"]`; `render/html.py base_css` appends `decor.css(style)`. Options: `--decor`, `--decor-corner|header|background|strength|corner-at|theme`, wizard block `#decor-opts` (shown for products with `ProductType.decor_ok`), `decor:` in moneyhub.yaml, live preview `/api/preview.png?decor_*`. Pictures are original line art in `decor.M` (no third-party art). Backgrounds are tested for text contrast (`decor.tint`); a background adds an ink note to the listing and Start-Here page. E-ink stays plain; unsupported products raise when options are explicit. New printable types that use the `header` macro should set `decor_ok = True`.

## New product type checklist
1. `products/<key>.py` subclass, `@register`, import in `products/registry.py` `_load_all`; templates in `products/templates/` (reuse `coloring.html.j2` or `oracle.html.j2`/`montessori.html.j2`).
2. Niche-free products: `niche_in_copy = False`, `copy_audience`, `title_suffix`, `how_steps`, `self.unique_title(ctx, name)`.
3. `listing/kit.py` `_TYPE_WORDS`, `web/guide.py` entry, `exports/kdp.py` SUPPORTED / `web/app.py` `pdf_types` for print books, `render/mockups.py` FAMILIES.
4. CLI option in `cli.py make()`, web field in `web/app.py create_job` + `start.html` + `start.js` (+ classic `index.html`/`app.js`); validate in both CLI and web.
5. Tests in `tests/test_art_formats.py`, docs in `docs/art-formats.md`, re-run `scripts/record_tour.py` if the wizard changed.
